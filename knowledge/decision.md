# 待決策與驗收建議

## 遊戲節奏是否需要調整

**狀態：** 等待實際遊玩觀察。

目前每 690 毫秒出現一顆星星，星星約 2.4 秒後消失，金星機率為 20%。僅依程式參數無法可靠判斷節奏是否太快、太慢或目標是否太小；現在直接改動會把主觀猜測當成體驗證據。

**建議：** 先在桌面及手機各玩 2 至 3 局，記下是否有看不清、點不中、星星太密／太疏、音效不合適，以及常見分數區間。只有觀察到穩定問題，再一次調整一項參數並重玩比較。若沒有明顯問題，保留目前設定。

## 實機驗收清單

- [x] 桌面尺寸瀏覽器（1024×768 CSS viewport）：開始、普通星星計分、倒數結束、最佳紀錄與再玩一次；瀏覽器確認音效按鈕 `aria-pressed` 能切換。
- [x] 手機比例瀏覽器 viewport（390×844 CSS px）：確認遊戲與結算畫面完整顯示；這不是實體觸控驗收。
- [ ] 實體手機：直向與橫向版面、頁面縮放、垂直捲動與觸控命中。
- [ ] 新版部署後重新驗收鍵盤：Tab 可移至開始按鈕及星星，Enter 可開始及收集；收集後焦點留在下一目標或遊戲區。
- [ ] 實際聽音效、跨重新載入確認最佳紀錄保存，並確認減少動態效果偏好。

**推薦驗收方式：** 完成上列操作後，把出現的具體問題與裝置／瀏覽器記錄下來，再依證據調整。Node smoke test 不能取代真實視覺、音效與觸控驗收。

**本次瀏覽器觀察（2026-11-27）：** 1024×768 viewport 下 app 寬 470px、遊戲區寬約 435px、高約 424px，頁面尺寸與 viewport 相同，未見捲動溢出；普通星星可加 1 分，計時到 0 後顯示結算，重玩分數歸零且最佳紀錄 26 保留。390×844 viewport 的結算卡可完整呈現。音效按鈕 `aria-pressed` 由 true→false→true。Tab/Enter 可開始與收集星星；初測發現收集後焦點掉回頁面，已修正程式並新增回歸測試，部署後需再在正式站確認。這些結果只證明瀏覽器中的 viewport 與 DOM 操作；目前沒有測量實體觸控精度或實際音訊輸出，因此不據此調整遊戲節奏，也不勾選手機實測。

## 短回合切到背景時的計時規則

**狀態：** 已採用推薦作法。

**決定：** 30 秒回合照常經過真實時間；玩家切回頁面時立即更新剩餘時間，時間已到就直接結算。分頁隱藏時不再生成星星並清掉現存目標。

**理由：** 這是短局挑戰，讓它在背景自動暫停會使「30 秒」變得不一致。若未來設計長局或暫停型玩法，再改成凍結剩餘時間。
